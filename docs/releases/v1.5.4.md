# v1.5.4 — fail-closed EMS execution and three-day forecasting

## User update steps / Kroki po aktualizacji

1. **HACS:** before updating, keep RCEm in shadow mode and disable every
   automatic or scheduled EMS writer. Update **Hoymiles HIT xxL G3 Modbus** to
   **v1.5.4**.
   Przed aktualizacją pozostaw RCEm w trybie shadow i wyłącz wszystkie
   automatyczne oraz harmonogramowe zapisy EMS. Zaktualizuj integrację
   **Hoymiles HIT xxL G3 Modbus** w HACS do **v1.5.4**.
2. **Home Assistant:** restart after the HACS update. The integration installs
   the managed EMS package during startup, so validate the configuration and
   restart once more when the Repair notification requests it. Keep all writers
   disabled throughout both restarts and hard-refresh every open Hoymiles
   dashboard tab to load frontend URL `v=1.5.4.17`.
   Po aktualizacji HACS uruchom Home Assistant ponownie. Integracja instaluje
   zarządzany pakiet EMS podczas startu, dlatego sprawdź konfigurację i wykonaj
   jeszcze jeden restart, gdy zażąda tego komunikat Napraw. Podczas obu
   restartów pozostaw zapisy wyłączone i twardo odśwież każdą otwartą kartę
   dashboardu Hoymiles, aby wczytała URL frontendu `v=1.5.4.17`.
3. **ESP32 / ESPHome:** only after the Home Assistant no-write verification,
   rebuild and upload firmware from the top-level ESPHome file pinned to
   **v1.5.4**. HACS does not flash the ESP32. The firmware update is required
   for the new physical BMS and capacity-reporting contract.
   Dopiero po odczytowej weryfikacji Home Assistanta skompiluj i wgraj firmware
   z głównego pliku ESPHome przypiętego do **v1.5.4**. HACS nie wgrywa firmware
   ESP32. Aktualizacja firmware jest wymagana dla nowego kontraktu raportowania
   fizycznego BMS i pojemności.
4. **Verification / Weryfikacja:** confirm that the physical EMS mode and the
   complete `4300–4306` block did not change during the update, no execution
   owner became active, the managed package reports **1.5.4 / Ready**, each
   optimizer publishes a current result or an explicit fail-closed reason,
   Solcast Day 3 is fresh when enabled, and all Aurora views render. After the
   firmware upload confirm repeated fresh register-4102 reports. Parallel
   Master/Slave acceptance still requires every inverter on the same external
   RS485 bus and separate observation of every unit.
   Potwierdź, że podczas aktualizacji nie zmieniły się fizyczny tryb EMS ani
   pełny blok `4300–4306`, nie pojawił się aktywny właściciel, pakiet zarządzany
   pokazuje **1.5.4 / Gotowe**, każdy planer publikuje aktualny wynik albo jawny
   bezpieczny powód blokady, opcjonalny Dzień 3 Solcast jest świeży, a wszystkie
   widoki Aurora działają. Po wgraniu firmware potwierdź powtarzające się świeże
   raporty rejestru 4102. Odbiór Master/Slave nadal wymaga wszystkich falowników
   na tej samej zewnętrznej magistrali RS485 i osobnej obserwacji każdej jednostki.

## What changed / Co się zmieniło

- The known-good address-`0` FC16 broadcast writes the complete EMS block
  `4300–4306`. Success still requires an exact later FC03 readback from the
  physical Master. This is Master configuration acknowledgement, not a claim
  that every Slave acknowledged the command.
- Parallel EMS requires the ESP32 converter, Master and every Slave on one
  physical external Modbus/RS485 bus. Internal parallel addresses remain
  topology diagnostics and are not external Modbus unit IDs.
- Direct registers `258`, `259` and `306` remain fail-closed on Master/Slave
  until their broadcast semantics are proven.
- Every delayed RCE, tariff, balancing and RCEm action revalidates current
  policy, ownership, conflict, source freshness, physical mode and the committed
  plan immediately before later writes and after acknowledgements. Off-Grid
  code `3` has priority and is never overwritten by automatic cleanup.
- RCE, tariff and RCEm withdraw `result_current` when a consumed input changes
  during calculation. Configured Solcast entities are tracked dynamically;
  optional Day 3 extends the tariff horizon, while missing or stale Day 3 keeps
  the conservative shorter-horizon fallback.
- Stable physical BMS limits and battery capacity now have explicit provenance.
  Register `4102` is polled by the 20-second settings controller with unchanged
  values reported; RCEm accepts a positive stable capacity while dynamic BMS
  voltage and current limits remain strictly freshness-gated.
- Battery balancing requires the complete 99.9% hold interval, execution-owner
  diagnostics report real active control, and Aurora exposes the Day 3 source
  and freshness diagnostics without changing the canonical strategy module.

## Parallel acceptance boundary / Granica odbioru równoległego

Aggregate physical-response acknowledgement is not implemented in v1.5.4.
The previously proven shared-bus broadcast path is restored, but the current
field acceptance remains pending until the ESP32, Master and every Slave are
again connected to the same external RS485 bus and Grid Discharge plus Self-Use
are observed separately on every inverter. Master FC03 alone is not per-Slave
acknowledgement.

Sumaryczne potwierdzenie odpowiedzi fizycznej nie jest zaimplementowane w
v1.5.4. Przywrócono wcześniej sprawdzoną ścieżkę broadcastu na wspólnej
magistrali, lecz aktualny odbiór terenowy pozostaje odroczony do chwili, gdy
ESP32, Master i każdy Slave ponownie znajdą się na tej samej zewnętrznej
magistrali RS485, a Grid Discharge i Self-Use zostaną sprawdzone osobno na każdej
jednostce. FC03 Mastera nie jest potwierdzeniem każdego Slave'a.
